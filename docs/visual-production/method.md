# Методика библиотеки

Как собраны и проверены сведения, что значат оценки и метки. Читать перед правкой карточек.

## Охват

- Библиотека покрывает основные классы инструментов, не все существующие решения.
- Карточка есть у каждого существенного решения класса. Остальные упомянуты одной строкой в обзоре класса, со ссылкой на официальный сайт.
- Код не устанавливался и не запускался. Платные модели и подписки не использовались. Поэтому «что реально получается» опирается на опубликованные примеры, документацию и галереи, а не на собственные пробы.

## Проверка фактов

- Только первоисточники: официальный сайт, документация, репозиторий, страница цен, лицензия, условия использования. Обзоры и форумы допустимы лишь как дополнение, с пометкой.
- У каждого факта о цене, лицензии и активности есть дата проверки. Основная дата этой версии: 2026-10-14.
- Цифры GitHub (звёзды, последний push, последний релиз, лицензия по SPDX) вставлены скриптом из GitHub API в день проверки. В карточке они стоят между метками `gh-stats`.
- Что не удалось проверить, записано в разделе «Неизвестно» карточки. Пустой раздел значит: всё проверено.
- Примеры видео и демо: ссылка открывалась при проверке. Ролики YouTube проверены через oEmbed (название и канал совпадают).

## Типы сцен

Ключ типа стоит в поле `scenes` карточки: для каких сцен инструмент хорош.

- `formula` — вывод формул, математика на экране.
- `graph` — графики функций и данных.
- `diagram` — схемы, процессы, блок-диаграммы.
- `mechanism` — устройство предмета, как он работает.
- `field` — невидимые явления: поля, потоки, волны.
- `micro` — микромир: атомы, молекулы, домены, клетки.
- `scale` — смена масштаба, космос, «от кухни до атома».
- `simulation` — физически точное движение: жидкость, частицы, механика.
- `character` — персонажи, сюжет, юмор.
- `drawing` — рисование и объяснение вживую.
- `real-footage` — реальная съёмка с графикой поверх.
- `typography` — кинетическая типографика, заголовки, цитаты.
- `map-timeline` — карты и хронологии.
- `screen` — интерфейсы, код, экран компьютера.

## Оценки

Все оценки от 1 до 5, кроме стоимости. Каждая оценка объяснена в тексте карточки.

- `quality` — потолок качества для объясняющего видео. 1: простая графика. 3: аккуратная учебная графика. 5: уровень лучших научно-популярных каналов.
- `human_difficulty` — трудность для человека. 1: освоить за день без опыта. 3: недели, нужен опыт в графике или коде. 5: месяцы, профессиональный инструмент.
- `agent_difficulty` — трудность для ИИ-агента. 1: агент делает сцену кодом или из командной строки и сам проверяет рендер. 3: агент пишет скрипты, но часть работы руками в интерфейсе. 5: только ручная работа в интерфейсе.
- `automation` — автоматизация. 1: нет API и скриптов. 3: есть скрипты или шаблоны, но не всё. 5: всё из кода или командной строки, пакетный рендер.
- `reproducibility` — воспроизводимость. 1: результат зависит от ручных действий или случайности. 3: проектный файл воспроизводит результат, но он двоичный. 5: текстовый проект под git, тот же код даёт тот же кадр.
- `cost` — стоимость для монетизируемого канала. 0: бесплатно. 1: до $20 в месяц или разовая покупка до $100. 2: $20–100 в месяц или разовая покупка до $500. 3: дороже. `?`: цена не публикуется, только по запросу.

## Зрелость

Поле `maturity`:

- `experimental` — прототип, исследовательский код.
- `young` — моложе двух лет или до версии 1.0, API меняется.
- `stable` — стабильные релизы, живое сообщество.
- `standard` — отраслевой стандарт.
- `declining` — развитие замедлилось, мало релизов.
- `abandoned` — нет релизов и коммитов больше двух лет или проект закрыт.

## Права

Права на код и права на результат различаются. В карточке три строки:

- Код или программа: лицензия (SPDX) или вид коммерческой лицензии.
- Результат: кому принадлежат кадры и ролики, есть ли ограничения на коммерческое использование, монетизацию YouTube, водяной знак.
- Ассеты в комплекте: шаблоны, модели, шрифты, звуки из поставки и их условия.

Это сведения из условий использования, не юридическая консультация.

## Как обновлять

1. Новый инструмент: скопировать [шаблон](templates/tool-card.md) в `tools/<id>.md` и заполнить.
2. Добавить строку в обзор класса.
3. Пересобрать таблицы: `python3 docs/visual-production/scripts/build_tables.py`.
4. Обновить цифры GitHub: `python3 docs/visual-production/scripts/gh_stats.py`.
5. Поставить новую дату проверки в изменённых полях.
