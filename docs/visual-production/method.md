# Методика библиотеки

Как собраны и проверены сведения, что значат оценки и метки. Читать перед правкой карточек.

## Охват

- Библиотека покрывает основные классы инструментов, не все существующие решения.
- Карточка есть у каждого существенного решения класса. Остальные упомянуты одной строкой в обзоре класса, со ссылкой на официальный сайт.
- Код не устанавливался и не запускался. Платные модели и подписки не использовались. Поэтому «что реально получается» опирается на опубликованные примеры, документацию и галереи, а не на собственные пробы.
- Оценки, сроки и сравнения «лучше, хуже» — предварительные экспертные оценки по этим материалам, не измерение. Перед выбором для канала нужен пилот.

## Проверка фактов

- Основа — первоисточники: официальный сайт, документация, репозиторий, страница цен, лицензия, условия использования. Где первоисточник недоступен (страница закрыта для ботов, цена только по запросу), карточка берёт вторичный источник с пометкой или пишет «неизвестно». Обзоры и форумы — только дополнение, с пометкой.
- У каждого факта о цене, лицензии и активности есть дата проверки. Основная дата этой версии: 2026-10-14.
- Цифры GitHub получены в день проверки служебным скриптом; в проект он не сохранён, ручной порядок — в разделе [«Цифры GitHub»](#цифры-github). Звёзды, лицензия по SPDX и признак архива — из GitHub API. Последний коммит основной ветки и последний релиз или тег — из Atom-лент репозитория. Дата последнего push по API есть только в [tables/github.csv](tables/github.csv). В карточке цифры стоят между метками `gh-stats`.
- Что не удалось проверить, записано в разделе «Неизвестно» карточки. Раздел перечисляет найденные пробелы, а не все: короткий или пустой раздел не гарантирует, что остальное проверено.
- Примеры видео и демо: ссылка открывалась при проверке. Для роликов YouTube проверка через oEmbed подтверждает только доступность, название и канал, но не содержание и качество движения. Если карточка не говорит о просмотре, содержание ролика описано по названию и описанию.

## Типы сцен

Ключ типа стоит в поле `scenes` карточки: для каких сцен инструмент хорош.

- `formula` — вывод формул, математика на экране.
- `graph` — графики функций и данных.
- `diagram` — схемы, процессы, блок-диаграммы.
- `mechanism` — устройство предмета, как он работает.
- `field` — невидимые явления: поля, потоки, волны.
- `micro` — микромир: атомы, молекулы, домены, клетки.
- `scale` — смена масштаба, космос, «от кухни до атома».
- `simulation` — физически точное движение: жидкость, частицы, механика.
- `character` — персонажи, сюжет, юмор.
- `drawing` — рисование и объяснение вживую.
- `real-footage` — реальная съёмка с графикой поверх.
- `typography` — кинетическая типографика, заголовки, цитаты.
- `map-timeline` — карты и хронологии.
- `screen` — интерфейсы, код, экран компьютера.

## Оценки

Все оценки от 1 до 5, кроме стоимости. Каждая оценка объяснена в тексте карточки. Оценки качества, сложности, автоматизации и воспроизводимости — предварительные экспертные оценки авторов карточек без собственных проб, не измерение.

- `quality` — потолок качества для объясняющего видео. 1: простая графика. 3: аккуратная учебная графика. 5: уровень лучших научно-популярных каналов.
- `human_difficulty` — трудность для человека. 1: освоить за день без опыта. 3: недели, нужен опыт в графике или коде. 5: месяцы, профессиональный инструмент.
- `agent_difficulty` — трудность для ИИ-агента. 1: агент делает сцену кодом или из командной строки и сам проверяет рендер. 3: агент пишет скрипты, но часть работы руками в интерфейсе. 5: только ручная работа в интерфейсе.
- `automation` — автоматизация. 1: нет API и скриптов. 3: есть скрипты или шаблоны, но не всё. 5: всё из кода или командной строки, пакетный рендер.
- `reproducibility` — воспроизводимость. 1: результат зависит от ручных действий или случайности. 3: проектный файл воспроизводит результат, но он двоичный. 5: текстовый проект под git, тот же код даёт тот же кадр.
- `cost` — стоимость для монетизируемого канала. 0: бесплатно. 1: до $20 в месяц или разовая покупка до $100. 2: $20–100 в месяц или разовая покупка до $500. 3: дороже. `?`: цена не публикуется, только по запросу.

## Зрелость

Поле `maturity`:

- `experimental` — прототип, исследовательский код.
- `young` — моложе двух лет или до версии 1.0, API меняется.
- `stable` — стабильные релизы, живое сообщество.
- `standard` — отраслевой стандарт.
- `declining` — развитие замедлилось, мало релизов.
- `abandoned` — нет релизов и коммитов больше двух лет или проект закрыт.

## Права

Права на код и права на результат различаются. В карточке три строки:

- Код или программа: лицензия (SPDX) или вид коммерческой лицензии.
- Результат: кому принадлежат кадры и ролики, есть ли ограничения на коммерческое использование, монетизацию YouTube, водяной знак.
- Ассеты в комплекте: шаблоны, модели, шрифты, звуки из поставки и их условия.

Это сведения из условий использования, не юридическая консультация.

## Как обновлять

1. Новый инструмент: скопировать [шаблон](templates/tool-card.md) в `tools/<id>.md` и заполнить.
2. Добавить строку в обзор класса.
3. Если в шапке карточки `github` не `none`: обновить цифры GitHub в карточке и в `tables/github.csv` (раздел «Цифры GitHub» ниже).
4. Обновить `tables/tools.csv` и `tables/by-scene.csv` (раздел «Таблицы» ниже).
5. Поставить новую дату проверки в изменённых полях.
6. Проверить шапку: все поля заполнены, значения `class`, `scenes`, `maturity`, оценок и `cost` — из списков этой методики.
7. Проверить ссылки: каждая относительная ссылка Markdown в изменённых файлах ведёт на существующий файл.

### Цифры GitHub

Источники для репозитория `owner/repo`:

- `https://api.github.com/repos/owner/repo` — звёзды (`stargazers_count`), лицензия (`license.spdx_id`), признак архива (`archived`), дата последнего push (`pushed_at`). Без ключа GitHub отвечает на 60 запросов в час.
- `https://github.com/owner/repo/releases.atom` — последний релиз или тег: первая запись ленты, имя тега из её ссылки, дата из поля `updated`.
- `https://github.com/owner/repo/commits.atom` — последний коммит основной ветки: дата из поля `updated` первой записи.

В карточке строки между `<!-- gh-stats:owner/repo -->` и `<!-- /gh-stats -->` заменить шестью строками:

- `- Звёзды GitHub: 15 480` — число с пробелом между разрядами.
- `- Последний коммит в основной ветке: ГГГГ-ММ-ДД`. Лента коммитов не открылась — «лента коммитов не получена», дату push не подставлять.
- `- Последний релиз или тег: v0.4.6 (ГГГГ-ММ-ДД)`. Лента пуста — «релизов и тегов в ленте нет».
- `- Лицензия по данным GitHub: MIT`. Пусто или `NOASSERTION` — «GitHub не определил, см. «Лицензия и права»».
- `- Репозиторий в архиве: да` или `нет`.
- `- Источник: GitHub API и Atom-ленты репозитория owner/repo, получено ГГГГ-ММ-ДД.`

В `tables/github.csv` строка карточки: `id`, `repo`, `stars`, `license` (`нет`, если лицензии нет), `archived` (`да` или `нет`), `pushed`, `last_commit` (пусто, если лента не открылась), `last_release`, `last_release_date`, `checked` (дата получения). Строки по `id` в алфавитном порядке. Карточка с `github: none` строки не имеет.

### Таблицы

`tables/tools.csv` — одна строка на карточку:

- Столбцы по порядку: `id`, `name`, `class`, `kind`, `scenes`, `quality`, `human_difficulty`, `agent_difficulty`, `automation`, `reproducibility`, `cost`, `price`, `maturity`, `platforms`, `export`, `code_license`, `gh_stars`, `gh_last_commit`, `gh_last_release`, `site`, `github`, `checked`, `card`.
- Значения — из шапки карточки; списки через «; ». `gh_stars`, `gh_last_commit`, `gh_last_release` — из `stars`, `last_commit`, `last_release` в `tables/github.csv`, пусто без репозитория. `card` — `tools/<id>.md`.
- Порядок строк: по первому классу карточки в порядке раздела «Классы», внутри класса — по `id`.

`tables/by-scene.csv` — одна строка на пару «тип сцены — карточка» из поля `scenes`:

- Карточки, у которых единственный класс `sync`, не входят: голос и метки нужны любой сцене.
- Столбцы: `scene`, `id`, `name`, `quality`, `human_difficulty`, `agent_difficulty`, `cost`, `price`, `card`.
- Порядок: по типу сцены в порядке раздела «Типы сцен», затем `quality` по убыванию, затем `cost` в порядке 0, 1, 2, 3, `?`, затем `id`.

Формат обоих файлов: UTF-8, разделитель — запятая, перевод строки LF, первая строка — названия столбцов. Поле с запятой, кавычкой или переводом строки берётся в двойные кавычки, кавычка внутри удваивается.
