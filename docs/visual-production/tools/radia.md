# Radia (ESRF)

Программа для расчёта трёхмерной магнитостатики, созданная в Европейском центре синхротронного излучения (ESRF, Гренобль) для ондуляторов и вигглеров из постоянных магнитов, катушек и мягкого железа. Метод граничных интегралов: объёмы разбиваются на блоки с однородной намагниченностью, воздух не покрывается сеткой, поле считается в любой точке пространства. Есть Python-интерфейс. Выводит числа, не картинки и не видео.

Не путать с одноимённым ответвлением ksugahar/Radia (пакет `radia` на PyPI): оно развивается отдельно, см. «Активность и зрелость».

## Что реально получается

- Постоянные магниты (блоки с заданной остаточной намагниченностью), катушки, железо с линейной или нелинейной кривой намагничивания (материалы `MatLin`, `MatSatIso`; в примерах на Python используется `rad.MatSatIsoFrm`, расчёт запускает `rad.Solve`). Это сразу покрывает магнит с железной пластиной.
- Расчёт поля в любой точке (`Fld`), по списку точек (`FldLst`), интегралы поля, энергия, силы и моменты на объектах (`FldFrc`, `FldEnrFrc`, `FldEnrTrq`). Для магнита на холодильнике это сила прижима.
- Сквозной пример (полосатый магнит на холодильнике). Многополюсная полоса собирается из блоков `ObjRecMag` с чередующейся намагниченностью, дверь — блок из железа, разбитый на подблоки (`ObjDivMag`) с материалом `MatSatIso`. После `Solve` поле читается в сетке точек, на выходе числа. Линии поля и карту рисуете сами (Matplotlib, PyVista), как в связке с [magpylib](magpylib.md). Готового примера «магнит на холодильнике» у Radia нет, проверка только по аналогии с ондулятором.
- Железо учитывается, чего не умеет [magpylib](magpylib.md) (только метод изображений). Для двери холодильника это важное отличие.
- Анимация: параметры (положение магнита, зазор) задаются в цикле, кадры считаются и рисуются отдельно. Нет встроенной анимации, камеры, переходов, рисования линий. Подробности про картинку и озвучку: связка с [matplotlib](matplotlib.md), [pyvista](pyvista.md) и [ffmpeg](ffmpeg.md).
- Окно Radia (OpenGL, QuickDraw 3D, Mathematica): быстрый просмотр геометрии для проверки, не для видео.

## Слабые стороны

- Метод даёт однородную намагниченность внутри каждого блока. Для железа нужно вручную разбивать на подблоки: автоматического разбиения нет, подбирать нужно так, чтобы поле в контрольных точках перестало меняться (документация, «Important Notes»).
- Рядом с поверхностью разбитого железа поле искажено: «поле снаружи, но у самой поверхности, может быть искажено подразбиением» (Known Problems, п. 4). Магнит на двери лежит у самой поверхности, поэтому точность у стыка надо проверять отдельно.
- Релаксация (итерации) иногда не сходится при неудачной форме объектов (одно измерение много меньше другого). Тонкая стальная пластина — как раз такой случай, нужно делить её на блоки с близкими размерами.
- Для нулевого деления координаты объектов слегка случайно сдвигаются при создании (`FldLenTol`), поэтому рисование поверхностей может искажаться, а результаты воспроизводятся с точностью до допуска.
- Документация написана под Mathematica и старые версии (ссылки на Windows 95/NT, Mac). Справочник по Python отдельно не нашёл: в Python имена короче (`rad.ObjRecMag` вместо `radObjRecMag` в Mathematica), как видно по примерам.
- Установка из исходников: нужно собрать C++ ядро и библиотеку FFTW 2.1.5 через Makefile, релизов и готовых пакетов у оригинала нет.
- Нет вихревых токов и движения.

## Сложность

- Для человека (4 из 5): физика ясна, но разбиение железа, проверка релаксации и сборка из исходников требуют опыта в магнитостатике и C++. Примеры в репозитории Python, но с устаревшим стилем.
- Для агента (3 из 5): скрипты на Python, числовые результаты, проверка по контрольным точкам. Сложные части — сборка, подбор разбиения и проверка сходимости; агенту нужны подсказки в виде эталонных значений (пример 01 даёт ожидаемые числа).

## Автоматизация и воспроизводимость

- Автоматизация (4 из 5): чистый Python, пакетные расчёты, примеры с параллельным запуском (`RADIA_TestParallel01.py`, вариант с mpi4py). Результат — массивы, графика отдельно.
- Воспроизводимость (4 из 5): модель — скрипт под git. Из-за случайного сдвига геометрии результат совпадает в пределах допуска, не побитово.

## Платформа и оборудование

C++ ядро и Python-модуль. В репозитории Makefile для gcc и macOS и проект Visual Studio для Windows. Нужен компилятор, FFTW 2.1.5 (скачивается Makefile). В репозитории лежит готовый `radia.pyd` для Windows (версия Python в файле не указана). Видеокарта не нужна. Память растёт как квадрат числа подблоков (матрица взаимодействия).

## Экспорт

Числа: поле, интегралы, силы. Графики, карты поля и анимации делают другие библиотеки. Встроенный просмотр геометрии (OpenGL, пример 02 использует `uti_plot`). Ролики и PNG из Radia сами не выходят.

Зрелость: `declining`. Метод и программа с 1997 года (первая версия — апрель 1997, на странице ESRF версия 4.1), все ондуляторы ESRF с 1992 года считались Radia или её предшественниками. В репозитории 19 коммитов, последний 2026-05-07, ни тегов, ни релизов. Страница ESRF говорит, что Radia теперь поддерживает Oleg Chubar.

Рядом идёт ответвление [ksugahar/Radia](https://github.com/ksugahar/Radia) (автор Mitsutoshi Sugahara) с пакетом `radia` на PyPI, версия 5.3.2 от 2026-10-12, коммиты ежедневно: интеграция с NGSolve, MCP-сервер `radia-mcp`, MATLAB и Simulink, GPU. Колёса на PyPI только для Windows x64 и Python 3.12, лицензия составная (ядро по условиям BSD ESRF, часть MIT и MPL-2.0, библиотека Intel MKL в составе). Для работы с нашей задачей оно неочевидно: большая часть про инженерное CAE, а не про картинку.

## Когда брать и когда нет

- Брать: нужен расчёт в 3D с железом и постоянными магнитами и открытыми границами; сила прижима магнита к стали; сборки Хальбаха и ондуляторы; проверка Magpylib там, где важна сталь.
- Не брать: быстрые карты поля без железа ([magpylib](magpylib.md)); 2D-сечения со сталью и нелинейностью ([femm](femm.md)); сложные нелинейные задачи с конечно-элементной сеткой ([elmer-fem](elmer-fem.md), [comsol](comsol.md)); если нужен готовый красивый кадр, не числа.
