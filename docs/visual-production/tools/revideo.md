# Revideo

Ответвление Motion Canvas для программного создания видео: сцены на TypeScript, безголовый рендер одной функцией, плеер React для предпросмотра в браузере. Сделан под серверные сценарии и шаблонные ролики, а не под ручную работу в редакторе.

- GitHub: https://github.com/midrender/revideo (старый путь redotvideo/revideo перенаправляет сюда)
- Документация: https://midrender.com/revideo/docs

  - [Анимация в README](https://github.com/midrender/revideo) — кубик Рубика перемешивается сам: 54 наклейки в псевдо-3D и вращение слоя, нарисованные кодом в `draw()`.

## Что реально получается

- Те же приёмы, что в [motion-canvas](motion-canvas.md): генераторы, сигналы, твины, камера и узлы. Документация прямо отправляет за основами к руководству Motion Canvas.
- Дополнения форка: анимации Rive, 3D на three.js, шейдеры, фильтры, потоковый текст, HLS-видео, эмодзи, анимация кода.
- Видео и звук в сцене: `<Video/>` и `<Audio/>`, экспорт звука, кадровая синхронизация.
- Метки времени: в документации есть `waitUntil` с перетаскиванием события в редакторе (как в Motion Canvas). Есть ли редактор в текущей версии, не ясно (см. «Неизвестно»).
- Переходы и непрерывность: те же, что у Motion Canvas; пример `stitching-videos` склеивает ролики с анимацией перехода.
- Типографика: потоковый текст, субтитры по словам (пример Shorts).

## Слабые стороны

- Проект сменил владельца. Репозиторий был `redotvideo/revideo`, теперь `midrender/revideo`, и README называет Revideo «движком Midrender» (коммерческий сервис). Заботу об открытом коде определяет интерес компании.
- Версия 0.x, API меняется (есть руководства по обновлению 0.2 → 0.3, 0.3 → 0.4, 0.5 → 0.10).
- Перерыв в релизах: после 0.10.4 (2025-02-24) следующий 0.11.0 вышел только 2026-07-10.
- Скорость рендера зависит от видео внутри сцены: сцены с `<Video/>` рендерятся намного медленнее, декодер зависит от формата (mp4 через WebCodecs, WebM через FFmpeg). Параллельные воркеры требуют много памяти.
- Нет математических примитивов, не заметны примеры научно-популярного уровня: примеры — шаблоны, Shorts и демо.
- Телеметрия: Revideo анонимно считает число рендеров через PostHog; отключается `DISABLE_TELEMETRY=true`.

## Сложность

- Для человека (3 из 5): TypeScript и модель генераторов, как у Motion Canvas. Серверный рендер добавляет Node, FFmpeg и браузер без экрана.
- Для агента (2 из 5): сцена — обычный TypeScript, рендер функцией `renderVideo()`. README заявляет, что сцену может написать Claude или Codex по запросу. Нет подтверждения, что агент сам сверяет кадры без дополнительной обвязки; документация по сравнению с Remotion скромнее.

## Автоматизация и воспроизводимость

- Автоматизация (4 из 5): `renderVideo()`, конечная точка рендера через CLI, параллельные воркеры (`workers`), `renderPartialVideo()`, примеры Google Cloud Run и AWS Lambda.
- Воспроизводимость (4 из 5): проект — TypeScript и `project.meta` под git; параметры подаются переменными проекта. Кадры рисует браузер, результат зависит от версии браузера и шрифтов.

## Платформа и оборудование

Node.js и безголовый браузер; в документации есть раздел о проблемах с FFmpeg, то есть он нужен. Работает везде, где работают они, включая Google Cloud Run. Предпросмотр — React-компонент `<Player/>` в браузере. Для ускорения: `resolutionScale: 0.5` в `project.meta` в два раза ускорил рендер у авторов; MP4 лучше других форматов.

## Экспорт

- Видео MP4 через FFmpeg (`FFmpegExporterClient`), покадровый вывод изображений (`ImageExporterOptions`).
- Прозрачное видео на входе: нужен VP9 в WebM; HEVC теряет прозрачность при рендере.
- Параметры рендера: разрешение, масштаб, частота кадров в настройках проекта и `renderVideo()`. Точные поддерживаемые кодеки на выходе не проверял.

## Когда брать и когда нет

- Брать: серверный или пакетный рендер шаблонных роликов на TypeScript, встроенный предпросмотр в своём веб-приложении, когда Motion Canvas нужен без браузерной ручной работы.
- Не брать: ручной подбор ритма под голос в редакторе без проверки, что он есть в нужной версии; сложную математику (лучше [manim-ce](manim-ce.md)); если нужна понятная лицензионная модель и плановая поддержка ([remotion](remotion.md) даёт платную).
