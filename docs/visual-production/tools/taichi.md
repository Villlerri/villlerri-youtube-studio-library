# Taichi Lang

Параллельный язык, встроенный в Python. Функции с декоратором `@ti.kernel` компилируются в код для CPU или GPU (CUDA, Vulkan, OpenGL, Metal). Используется для быстрых собственных симуляций: частицы, жидкости, упругие тела, метод материальных точек. Готовых «ролик-сцен» не даёт: физику и визуализацию пишет автор.

## Что реально получается

Сквозной пример (магнит на холодильнике). Магнитных пакетов у Taichi нет. Поле можно считать собственным ядром, но для магнитов дешевле [magpylib](magpylib.md). Taichi нужен для другого: частицы, ферромагнитная жидкость, песок, ткань, упругие тела. Для магнита на холодильнике разве что показать железные опилки как частицы в готовом поле.

Что даёт для объясняющего видео:

- Быстрые симуляции частиц и сред на одной видеокарте. Ролик автора показывает 100 миллионов частиц метода MLS-MPM (по названию ролика, оборудование в ролике не указано).
- Визуализация: встроенный `ti.GUI` и 3D-окно GGUI (`ti.ui.Window`) рисуют точки, линии, сетки. Безголовый режим: `show_window=False`, затем `window.save_image`. Видео: `ti.tools.VideoManager` пишет mp4 и gif, ему нужен ffmpeg. Команда `ti video` собирает mp4 из PNG.
- Для финального вида данные частиц обычно выносят в другие программы: [houdini](houdini.md), [blender](blender.md), [paraview](paraview.md).
- Плавные переходы: симуляция непрерывна во времени, её состояние можно менять между кадрами. Морфинга между сценами нет.
- Камера в GGUI настраивается кодом (`ti.ui.Camera`).
- Рисование линий и голос: нет.

## Слабые стороны

- Развитие почти остановилось (см. «Активность»). Последний релиз 1.7.4 от 2025-07-31, последние коммиты на 2025-07-30.
- Колёса PyPI собраны для Python 3.9–3.13. Для 3.14 колёс нет, а README в репозитории всё ещё называет Python 3.6–3.10 (устарело).
- Рендер встроенный простой. Красивая картинка требует внешней программы.
- Нужна видеокарта для скорости. Бэкенды CUDA, Vulkan, OpenGL 4.3+, Metal, CPU.
- Своя физика надо писать самому: модели материалов, граничные условия. Готовые решения в `taichi_elements`, но проект отдельный и не проверялся здесь.

## Сложность

- Для человека (3 из 5): Python-подобный синтаксис, но нужно мыслить параллельно (ядра, поля) и знать численные методы физики.
- Для агента (2 из 5): весь цикл кодом. Агент запускает расчёт и смотрит PNG. Затруднение: нужна видеокарта или CPU-бэкенд и отладка параллельных ядер.

## Автоматизация и воспроизводимость

- Автоматизация (5 из 5): Python-скрипт, безголовый режим, пакетная запись кадров.
- Воспроизводимость (3 из 5): код под git, но параллельные вычисления на GPU (атомарные операции) обычно недетерминированы. Строго детерминизм для всех ядер документацией не заявлен.

## Платформа и оборудование

Windows, Linux, macOS. Бэкенды: CPU x64 и ARM, CUDA, Vulkan, OpenGL (4.3+), Apple Metal; WebAssembly экспериментальный. Python 3.9–3.13 по колёсам PyPI.

## Экспорт

PNG (`window.save_image`, `ti.tools.imwrite`), mp4 и gif (`VideoManager` и `ti video` с ffmpeg), формат определяется расширением файла (PNG, JPG, BMP).

## Когда брать и когда нет

- Брать: нужна собственная быстрая симуляция частиц или жидкости, много данных, готовых инструментов под эту физику нет.
- Не брать: нужна надёжность на годы вперёд и поддержка новых версий Python. Для механики твёрдых тел проще [matter-js](matter-js.md) и [box2d](box2d.md). Для готовых жидкостей и частиц с отличной визуализацией — [houdini](houdini.md) и [blender](blender.md).
