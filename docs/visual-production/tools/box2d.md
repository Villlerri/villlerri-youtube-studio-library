# Box2D

Эталонный 2D-физический движок для игр на C17 автора Эрина Катто. Версия 3 переписана заново: многопоточность, SIMD, мягкий решатель шагов, заявленный детерминизм между платформами. Рисовать приходится самому: в комплекте только отладочные примеры на OpenGL.

## Что реально получается

Сквозной пример (магнит на холодильнике). Магнитных сил нет. Магнитик можно моделировать телом, к которому приложена сила притяжения, зависящая от расстояния. Поле при этом не видно. Для картинки поля это не подходит.

Что даёт для объясняющего видео:

- Сцены из твёрдых тел: стопка, цепная реакция, рычаги, шарниры, моторы, пружины, трение, упругость, игровые персонажи.
- Непрерывная обработка столкновений для быстрых тел, события контактов, лучи, сенсоры, фильтрация столкновений.
- Результат — позиции и углы тел в каждом шаге. Дальше их рисуют в [pixijs](pixijs.md), [p5js](p5js.md), [manim-ce](manim-ce.md) или другом рендере по выбору.
- Детерминизм: порядок симуляции определяется порядком создания тел, форм и соединений, результаты событий тоже в детерминированном порядке. Кросс-платформенный детерминизм достигнут на 64-битных платформах флагами компилятора и собственными функциями atan2, cos, sin (документация). Это значит, что запись симуляции воспроизводится.
- Непрерывность сцены: симуляция продолжается, камеру и оформление ведёте сами. Морфинга, рисования линий и привязки к голосу нет.

## Слабые стороны

- Движок без рендера и без экспорта. Нужен собственный код для вывода кадров.
- C-библиотека: нужно собрать (CMake) и написать оболочку или использовать порт на другой язык. Готовые обёртки для Python и JavaScript в проверенных страницах не изучались.
- Только 2D. Для объёмной механики есть новый проект автора [Box3D](https://github.com/erincatto/box3d) (3D-движок для игр, описан в README репозитория).
- Детерминизм не защищает ваш код: документация предупреждает, что приложение детерминированным не станет само.
- Физика игровая, не научная.

## Сложность

- Для человека (3 из 5): понятный C API и подробная документация, но надо собирать библиотеку и писать вывод картинок.
- Для агента (3 из 5): компилирует, пишет код, получает позиции тел и сам рисует кадры. Руки не нужны, но работа объёмная.

## Автоматизация и воспроизводимость

- Автоматизация (4 из 5): C-библиотека, скрипты сборки CMake, безголовый режим. Нет готового пакетного рендера кадров, он пишется вручную.
- Воспроизводимость (5 из 5): детерминизм между платформами и числом потоков заявлен в документации, на нём построен тест для каждого запроса слияния (pull request). Для бита в бит нужны одинаковые флаги компилятора.

## Платформа и оборудование

Windows, Linux, macOS (CMake-пресеты для всех трёх). Видеокарта нужна только примерам. Многопоточность и SIMD (SSE2, Neon) включены.

## Экспорт

Нет. Только данные состояния (позиции, углы). Кадры пишет ваш код.

## Когда брать и когда нет

- Брать: нужна воспроизводимая 2D-механика твёрдых тел, повторяемая на разных машинах, и вы готовы сами рисовать.
- Не брать: нужен быстрый путь от идеи до картинки в браузере — [matter-js](matter-js.md). Нужны жидкости и сложные среды — [taichi](taichi.md).
