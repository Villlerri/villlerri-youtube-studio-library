# GSAP

JavaScript-библиотека анимации (GreenSock Animation Platform): таймлайны, твины, плагины для рисования и морфинга SVG, разбора текста, движения по пути. Отраслевой стандарт веб-анимации. С 2025 года бесплатна целиком, вместе с бывшими платными плагинами. Видео сама не рендерит.

  - [DrawSVG](https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/) — линия «рисуется» по контуру SVG.

## Что реально получается

- Рисование линий и морфинг: плагины DrawSVG (штрих вырастает вдоль контура), MorphSVG (форма превращается в форму), MotionPath (объект едет по кривой). Это то, что нужно для «рисования вживую» в схемах и картах.
- Типографика: SplitText режет текст на символы, слова, строки для побуквенной анимации; ScrambleText перебирает символы до итогового текста. Кинетические заголовки и цитаты.
- Непрерывная сцена: один `gsap.timeline()` с вложенными таймлайнами и метками. Переходы между блоками внутри одного таймлайна идут без склеек, начало следующей анимации задаётся смещением от предыдущей.
- Макет: Flip анимирует перестройку раскладки (элемент переезжает на новое место).
- Камеры нет: «камеру» делают трансформацией контейнера (масштаб, перенос) или камерой three.js.
- Голос: встроенной синхронизации нет, метки времени задают числами или данными (например, из [whisperx](whisperx.md)).
- Формул, графиков и физики из коробки нет: это анимация значений, а не математическая библиотека. Есть Physics2D.

## Слабые стороны

- Видео из GSAP не получить без обвязки. GSAP тикает по часам браузера, а видео требует кадр как функцию времени. Рабочая схема: создать таймлайн на паузе и перематывать его на нужное время для каждого кадра. Так делают `@remotion/gsap` и HyperFrames.
- Лицензия не открытая: исходники читаются, но условия проприетарные, с запретом на конкурирующие визуальные конструкторы и правом Webflow менять условия.
- Это слой анимации, не движок сцены: вёрстку, SVG и рисование на экране делаете сами.
- Нет редактора на основе таймлайна для озвучки; GSDevTools только для отладки таймлайнов.

## Сложность

- Для человека (3 из 5): нужен JavaScript, HTML, CSS или SVG. API простое, но вёрстку сцены надо делать самому.
- Для агента (3 из 5): код агент пишет и проверяет легко. Получение видео требует отдельной обвязки: [remotion](remotion.md) с `@remotion/gsap`, HyperFrames или Puppeteer с покадровой перемоткой.

## Автоматизация и воспроизводимость

- Автоматизация (3 из 5): сама библиотека без командной строки. Командный рендер в видео появляется только вместе с Remotion или HyperFrames.
- Воспроизводимость (4 из 5): код под git, а таймлайн на паузе с перемоткой даёт тот же кадр для того же времени. Расходится, если анимация завязана на `requestAnimationFrame` или `setTimeout`.

## Платформа и оборудование

Браузер и любой JS-движок с DOM. Для рендера видео нужен headless Chromium (через Remotion или HyperFrames, последнему нужны Node.js 22 или новее и FFmpeg). Подключение: `npm install gsap` или CDN (jsDelivr).

## Экспорт

Только анимация в странице. Видео, прозрачность и частота кадров определяются обёрткой: Remotion или HyperFrames. Пакет `@gsap/react` даёт хук `useGSAP()`.

## Когда брать и когда нет

- Брать: кинетическая типографика, рисование линий и морфинг в SVG, плавные цепочки анимации внутри единого таймлайна, если у команды есть вёрстка и она уже собирает видео через [remotion](remotion.md).
- Не брать: как единственный инструмент для ролика (нужна обвязка для видео); для формул и графиков (лучше [manim-ce](manim-ce.md)); для встройки в продукт, конкурирующий с визуальным конструктором анимаций.
