# GLSL-шейдеры и Shadertoy

Метод: картинку считает не программа по объектам, а функция от координат пикселя и времени, которая выполняется на видеокарте для каждого пикселя. Язык этой функции — GLSL. Shadertoy — сайт, где такие функции пишут, запускают в браузере и публикуют.

## Ссылки

- Официальный сайт: https://www.shadertoy.com
- GitHub: открытого кода у сайта нет.
- Документация: страница справки Shadertoy (`/howto`) автоматическим запросам не открылась (Cloudflare, HTTP 403); состав входных данных взят со страниц шейдеров, найденных через поиск.
- Примеры, проверенные 2026-10-14 (ролики проверены через oEmbed, страницы Shadertoy не открывались):
  - [Painting a Character with Maths](https://www.youtube.com/watch?v=8--5LwHRhjk) — Inigo Quilez рисует мультяшного персонажа формулами в шейдере.
  - [I painted a Landscape with Mathematics](https://www.youtube.com/watch?v=BFld4EBO2RE) — тот же автор строит пейзаж одной функцией.
  - [Making a heart with Maths](https://www.youtube.com/watch?v=aNR4n0i2ZlM) — разбор: как из формулы получить форму и объём.
  - [Репозиторий glslViewer](https://github.com/patriciogonzalezvivo/glslViewer) — консольная утилита, которая запускает такие шейдеры без интерфейса.

## Что реально получается

- Поля и волны: электрические и магнитные поля, интерференция, дифракция, поток — это формулы по координатам, их и рисует шейдер. Сцены `field`, `micro`, `formula`.
- Масштаб и фракталы: бесконечные зумы и повторения считаются одной функцией (в роликах Quilez видны ландшафты и объёмные формы из формул).
- 3D без моделей: объёмные формы строят через функции расстояний и трассировку лучей прямо в шейдере. Камера — часть формулы, плавный облёт получается без склеек.
- Рисование линий: линия — функция расстояния до отрезка; долю длины ведут по времени. Приём делается кодом.
- Морфинг: формы смешивают математически; один шейдер переводит круг в квадрат без смены кадра.
- Типографика и текст: плохо. Шрифтов в GLSL нет, текст рисуют текстурой или формулами.
- Голос: входы звука на Shadertoy (`iChannel`, звуковые шейдеры, `iSampleRate`) для музыки; привязку к озвучке в ролике делают снаружи временем `iTime`.
- Потолок качества (5 из 5): ролики и шейдеры Quilez показывают картинку уровня лучших научно-популярных каналов; предел задаёт только мастерство автора.

## Слабые стороны

- Высокий порог по математике: векторы, функции расстояния, шум. Без опыта быстро не освоить.
- Нет выхода в видео: сайт показывает шейдер на лету. Для ролика нужно отдельно запускать шейдер и снимать кадры. Способы ниже.
- Скорость зависит от видеокарты: тяжёлый шейдер на слабом GPU идёт рывками при записи «с экрана».
- Сайт отвечал автоматическим запросам HTTP 403 (проверка Cloudflare): забрать шейдер оттуда скриптом при проверке не удалось. Есть ли у Shadertoy официальный программный доступ и на каких условиях, не выяснял.

## Сложность

- Для человека (4 из 5): нужен GLSL и математика (векторы, формулы форм). Простой узор за день, сцена с светом и камерой — месяцы.
- Для агента (2 из 5): весь код в тексте, результат проверяется кадром. Автономно агент работает через `glslViewer` (запуск без интерфейса, запись PNG). Руки нужны для художественной оценки и выбора лицензии.

## Автоматизация и воспроизводимость

- Автоматизация (4 из 5): шейдер — один текстовый файл. Видео собираются так:
  1. `glslViewer`: консольная программа с «headless rendering», экспортом изображений и последовательности PNG; в благодарностях README отмечена совместимость с шейдерами ShaderToy. Затем PNG склеивает [ffmpeg](ffmpeg.md).
  2. `shadertoy-render` (Python, использует ffmpeg): последний коммит в 2015 году, считать заброшенным.
  3. Браузер: оболочка WebGL вокруг шейдера, время `iTime = кадр / частота`; кадры снимает [ccapture-js](ccapture-js.md) или [remotion](remotion.md). Оболочку можно собрать на [three-js](three-js.md); руководство three.js по Shadertoy при проверке не открылось (404).
  4. Нодовые среды: например, GLSL TOP в [touchdesigner](touchdesigner.md). Перенос шейдеров вручную.
- Воспроизводимость (4 из 5): проект — текст под git, результат — чистая функция координат и времени. Небольшие различия возможны между видеокартами и драйверами.

## Платформа и оборудование

Shadertoy — браузер с WebGL. Локальный запуск через `glslViewer`: Linux, macOS, Windows (в вики репозитория есть инструкции), нужен OpenGL. Видеокарта обязательна для разумной скорости.

## Экспорт

Сам Shadertoy видео не экспортирует. Результат вне сайта: последовательность PNG из `glslViewer`, затем ffmpeg в MP4 или ProRes. Прозрачность зависит от формата кадров и оболочки.

## Лицензия и права

- Код или программа: GLSL — язык, лицензии на него нет. Утилита `glslViewer` — BSD-3-Clause. Исходники сайта Shadertoy закрыты.
- Результат: чужие шейдеры. Страница условий Shadertoy («What license will my Shaders have?», по выдаче поиска) говорит: автор владеет своим шейдером и сам выбирает лицензию; если не выбрал, действует Creative Commons Attribution-NonCommercial-ShareAlike 3.0 Unported. То есть по умолчанию нужны указание автора, некоммерческое использование и такая же лицензия на производные. Для канала с монетизацией чужой шейдер без явной разрешающей лицензии (например MIT, Apache 2.0 или CC0 в шапке кода) брать нельзя без согласия автора. Свои шейдеры — свободны.
- Ассеты в комплекте: текстуры и звуки, подключаемые к входам Shadertoy, имеют собственные условия; не проверял.

## Когда брать и когда нет

- Брать: фоны, поля, волны, фракталы и «математические» 3D-сцены, где важна красота и бесконечная плавность. Хорошо сочетается с формульными сценами в [manim-ce](manim-ce.md): шейдер как фон.
- Не брать: диаграммы, графики с подписями, текст, персонажей. Для них смотри [d3](d3.md), [manim-ce](manim-ce.md), [p5js](p5js.md). Не брать чужие шейдеры без проверки лицензии.
