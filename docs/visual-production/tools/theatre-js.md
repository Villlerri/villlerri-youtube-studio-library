# Theatre.js

JavaScript-библиотека анимации с визуальным редактором ключевых кадров прямо в браузере: таймлайн, графики кривых, пресеты плавности. Анимирует любые переменные JS, чаще всего сцены three.js и HTML/SVG. Видео не рендерит.

Публичная разработка остановлена: последний релиз вышел 2024-05-19. Для нового канала не рекомендуется.

## Что реально получается

- Ключевые кадры вручную с графиком кривых: движение объектов, камеры и света в сцене three.js, свойства DOM и SVG. Для ровного, «киношного» движения камеры по 3D-сцене это сильная сторона.
- Непрерывность: вся сцена живёт как набор объектов с анимируемыми свойствами в одной последовательности. Переходов между сценами как понятия нет: ведёте одну последовательность.
- Синхронизация с голосом: `sequence.attachAudio` проигрывает аудио вместе с последовательностью. Положение читается и задаётся (`sheet.sequence.position = 1`). Поэтому метки по озвучке расставляют ключами, а не словами.
- Рисование линий, морфинг, типографика: встроенных средств нет, это делает ваш код (three.js, SVG, GSAP и т. д.). Библиотека меняет только числа.
- Состояние проекта выгружается в JSON из Studio и подгружается в прод через `getProject('имя', {state})`.

## Слабые стороны

- Нет экспорта в видео. В прочитанных страницах документации (API core, последовательности, звук) вывода в видео нет. Кадры надо снимать самому: ставить `sequence.position` и сохранять кадр браузера (вывод из API, готового экспортёра не нашёл), либо делать связку с [remotion](remotion.md) или записью экрана.
- Развитие остановилось, см. «Активность и зрелость».
- В Studio ключи и кривые правят мышью. Агенту это недоступно без управления браузером.
- Лицензия Studio AGPL: годится для разработки, но в итоговую сборку Studio не включают.
- Ничего не знает о математике, формулах, графиках, диаграммах.

## Сложность

- Для человека (4 из 5): нужен JavaScript, обычно three.js, плюс навык работы с кривыми и ключами. Результат ювелирный, цикл «правка, просмотр» медленный.
- Для агента (4 из 5): код сцены агент пишет, но ключи и кривые ставят в Studio вручную, а видеоэкспорта нет, приходится строить свой захват кадров.

## Автоматизация и воспроизводимость

- Автоматизация (2 из 5): есть программное API (объекты, последовательности, `position`, `play`), но нет командного рендера и экспорта в видео.
- Воспроизводимость (4 из 5): состояние хранится в JSON-файле под git, код в JS. Захват кадров зависит от браузера.

## Платформа и оборудование

Браузер. Есть пакеты `@theatre/r3f` (React Three Fiber), `@theatre/react`, `@theatre/studio` (редактор). Видеокарта нужна для WebGL-сцен.

## Экспорт

Видео, GIF и кадры встроенных средств нет. Результат — JavaScript-анимация в странице и JSON состояния. Видео получают сторонней записью страницы или покадровой съёмкой браузера.

## Когда брать и когда нет

- Брать: только если нужен визуальный редактор кривых для сцены three.js внутри веб-приложения и приемлем риск остановки. Для роликов нужен свой захват кадров.
- Не брать: для нового канала, для вывода в видео, для формул и схем. Для камеры и 3D лучше [three-js](three-js.md) с ключами в коде, или [remotion](remotion.md) с `@remotion/three`; для кривых движения — [gsap](gsap.md).
