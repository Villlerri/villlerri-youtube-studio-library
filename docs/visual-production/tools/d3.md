# D3.js

JavaScript-библиотека для графики, управляемой данными: привязывает данные к элементам SVG, Canvas и HTML, считает шкалы, оси, формы, раскладки и карты. Видео сама не делает: даёт кадры в браузере, а запись берёт на себя другой инструмент.

## Ссылки

- Официальный сайт: https://d3js.org
- GitHub: https://github.com/d3/d3
- Документация: https://d3js.org/getting-started
- Примеры, проверенные 2026-10-14 (страницы открывались, ролики не смотрел):
  - [d3-transition](https://d3js.org/d3-transition) — переходы: DOM плавно меняется от текущего состояния к целевому. Цвета, числа, трансформации и строки с числами (в том числе пути) интерполируются сами.
  - [d3-interpolate](https://d3js.org/d3-interpolate) — набор интерполяторов для своих переходов.
  - [d3-timer](https://d3js.org/d3-timer) — таймер на `requestAnimationFrame`; важен для записи кадров, см. ниже.

## Что реально получается

- Графики и диаграммы: линии, столбцы, области, деревья, силовые раскладки, карты (`d3-geo`). Подходит для сцен `graph`, `diagram`, `map-timeline`.
- Плавное изменение данных: присоединение данных (enter, update, exit) и `transition()` переводят столбцы и линии из одного набора данных в другой без склеек. Объекты остаются теми же, а не заменяются кадром. Это прямой ответ на «повтор одного кадра».
- Рисование линий «вживую»: приём с длиной штриха (`stroke-dasharray`) в документации D3 не описан, но работает на любом SVG-пути и анимируется через `transition`. Для готового эффекта есть карточка [vivus](vivus.md).
- Камера: нет. Панорамирование и масштаб есть как взаимодействие (`d3-zoom`, `d3-brush` на главной странице), их можно вести кодом.
- Типографика: SVG-текст и HTML. Кинетической типографики и посимвольной анимации нет.
- Голос: нет таймлайна и привязки к аудио. Раскадровку под озвучку надо вести снаружи: [remotion](remotion.md), [gsap](gsap.md), [theatre-js](theatre-js.md).
- Потолок качества (4 из 5): графики и карты студийного уровня при хорошем дизайне; без отдельной работы над подачей выглядит как стандартная диаграмма.

## Слабые стороны

- Нет собственного экспорта в видео и нет таймлайна. Переходы запускаются по часам браузера, поэтому без подмены часов запись даёт дёрганье.
- Морфинг между произвольными формами (кружок в стрелку) встроенные интерполяторы строк делают только при одинаковой структуре пути. Для остального нужны сторонние библиотеки; проверка их не проводилась.
- Низкоуровневый API: красивый кадр с нуля требует недель вёрстки. Готовых «стилей объясняющего видео» нет.
- Страница Observable с галереей D3 при проверке отвечала HTTP 429, поэтому галерею в примеры не включил.

## Сложность

- Для человека (3 из 5): нужны JavaScript, SVG и идиома «привязка данных». Первый график за день, плавная сцена с переходами и дизайном — недели.
- Для агента (2 из 5): сцена целиком в коде, результат проверяется скриншотом в браузере. Рука нужна для вкуса и для настройки конвейера записи кадров.

## Автоматизация и воспроизводимость

- Автоматизация (3 из 5): пакетной записи у D3 нет. Её дают внешние инструменты: [remotion](remotion.md), [ccapture-js](ccapture-js.md) (виртуальные часы), Puppeteer-захват. Подробное сравнение способов в обзоре [SVG, Canvas, WebGL](../classes/03-web-graphics.md).
- Воспроизводимость (4 из 5): проект — текст под git. По документации `d3-timer` использует `requestAnimationFrame`, а `d3.now()` берёт время из `performance.now`. Подмена этих двух источников, как в CCapture, делает переходы покадрово повторяемыми. Это вывод из документации, запуском не проверен. Случайность (`Math.random`) надо фиксировать вручную.

## Платформа и оборудование

Любой современный браузер, видеокарта не нужна. Для записи на сервере нужен headless-браузер.

## Экспорт

- Сам D3 экспортирует разметку: SVG и HTML. SVG можно сохранить как файл.
- Видео: через внешний захват (MP4 или WebM через WebCodecs в CCapture, покадровый рендер в Remotion). Прозрачность зависит от выбранного способа записи.

## Когда брать и когда нет

- Брать: графики и карты, которые должны плавно меняться вместе с данными, диаграммы связей, шкалы и оси нужной формы. Лучше всего в связке с покадровым рендером из [remotion](remotion.md).
- Не брать: формулы и вывод выкладок ([manim-ce](manim-ce.md), [mathbox](mathbox.md)), 3D ([three-js](three-js.md)), ролики, где нужен готовый таймлайн и озвучка без самостоятельной сборки.
