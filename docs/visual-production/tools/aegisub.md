# Aegisub

Редактор субтитров с точной разметкой времени по волне и спектру звука. Привязывает строки и слова к голосу вручную, умеет караоке-тайминг по слогам и эффекты на языке разметки ASS. Автоматически слова не выравнивает.

## Что реально получается

- Тайминг по звуку. Волна и спектр звука, режимы расстановки для диалога и для караоке. Строки получают начало и конец по границам звука на экране.
- Слова и слоги. В режиме караоке время слова записывается тегом `\k`. Длительность задаётся в сотых долях секунды (10 мс) ([теги ASS](https://aegisub.org/docs/latest/ass_tags/)). Получается файл «слово подсвечивается, пока звучит».
- Эффекты. Теги ASS и шаблонизатор Karaoke Templater на Lua делают заливку, смещение и появление слов. Для объясняющего видео это титры и подписи, которые двигаются с голосом.
- Роль в конвейере студии. Озвучку делает [ElevenLabs](elevenlabs.md), у него есть метки времени. Aegisub нужен, чтобы вручную поправить автоматические субтитры из [WhisperX](whisperx.md) или [whisper.cpp](whisper-cpp.md), проверить границы по звуку и собрать ASS с оформлением. Файл ASS читается как текст и годится источником времён для анимации.
- Звук. Открывает почти любой формат через FFMS2. Только моно: многоканальный звук сводится автоматически.
- Видео. Версия 3.5.0 добавила панорамирование и масштаб видео, поддержку High-DPI, проверки соответствия разрешения и цветовой матрицы, нативные сборки для Apple Silicon.
- Непрерывность сцены, морфинг, камера — не его задача, он про текст.

## Слабые стороны

- Всё вручную. Автоматического выравнивания слов нет. Разметка длинного ролика — часы работы.
- Формат ASS заточен под субтитры. Для вставки в анимацию времена надо извлечь своим кодом.
- Режим только mono. Длинный сжатый звук декодируется в память целиком (нужно много ОЗУ).
- Экспорт в другие форматы, кроме ASS, убирает почти все теги оформления (документация экспорта).
- Рендеринг на экране зависит от libass. В видеоредакторах ASS поддерживается не везде.
- Безопасность. В примечаниях к 3.5.0 сказано о уязвимости CVE-2026-92705: открытие специально созданного файла субтитров могло запустить произвольный код через скрипты Automation, на которые он ссылается. В 3.5.0 исправлено. Чужие ASS-файлы открывать только в версии 3.5.0 или новее.

## Сложность

- Для человека (3 из 5): интерфейс с горячими клавишами, базовый тайминг осваивается за день, караоке и ASS-эффекты за недели.
- Для агента (4 из 5): основная работа в окне программы. Агент может создавать и править файлы ASS и SRT текстом и собирать их из меток других инструментов, но проверку по звуку и подгонку делает человек. Безголового режима командной строки в документации не нашёл.

## Автоматизация и воспроизводимость

- Автоматизация (2 из 5): внутри программы есть Automation на Lua (макросы, шаблонизатор караоке, менеджер скриптов). Пакетного режима без интерфейса не нашёл.
- Воспроизводимость (4 из 5): проект — текстовый файл ASS, который хорошо сравнивается в git. Тайминг ручной, поэтому повторить его с нуля нельзя, но готовый файл рендерится одинаково через libass.

## Платформа и оборудование

Windows (установщик; переносимый архив по README), macOS (Intel и Apple Silicon, подписанные сборки с версии 3.5.0), Linux (сборка из исходников по README через Meson). Видеокарта не обязательна. Память нужна под кэш декодированного звука.

## Экспорт

Сохранение в ASS (родной формат), экспорт в другие форматы, кроме ASS, с потерей тегов оформления (SRT и другие) и в разных кодировках. Фильтры экспорта: только видимые строки, шаблонизатор караоке, пересчёт частоты кадров, очистка тегов и другие.

## Когда брать и когда нет

- Брать: нужен ручной тайминг субтитров и слов по звуку, караоке-подсветка, стилизованные титры ASS, проверка автоматических меток.
- Не брать: когда нужно автоматическое выравнивание (тогда [WhisperX](whisperx.md), [Montreal Forced Aligner](montreal-forced-aligner.md) или Forced Alignment в [ElevenLabs](elevenlabs.md)). Когда агент должен вести работу целиком без интерфейса.
