# p5.js

JavaScript-библиотека творческого кодинга в духе Processing. Один холст, функции `setup()` и `draw()`, простые команды для фигур, цвета, шума и движения. Понятна новичку; ролики из неё получаются только через внешний захват кадров.

## Ссылки

- Официальный сайт: https://p5js.org
- GitHub: https://github.com/processing/p5.js
- Документация: https://p5js.org/reference/
- Примеры, проверенные 2026-10-14 (страницы открывались; ролики проверены через oEmbed):

  - [Creative Coding for Beginners with p5.js (1.1)](https://www.youtube.com/watch?v=yPWkPOfnGsw) — The Coding Train: вводный ролик, как выглядит рабочий процесс в редакторе.
  - [1.3: Basics of drawing](https://www.youtube.com/watch?v=D1ELEeIs0j8) — The Coding Train: рисование фигур в браузере.
  - [Справочник saveFrames](https://p5js.org/reference/p5/saveFrames/) и [saveGif](https://p5js.org/reference/p5/saveGif/) — встроенная запись.

## Что реально получается

- Графики, поля, частицы, простые симуляции, генеративные узоры. Сцены `graph`, `field`, `simulation`, `drawing`.
- Рисование линий вживую: точки добавляются в `draw()` по кадрам, линия растёт за курсором или по формуле. Это естественная модель p5.
- Режимы: `createCanvas` принимает рендерер P2D (по умолчанию) или WEBGL (справочник). Возможности 3D-режима и шейдеров в p5 2.x не изучал.
- Непрерывность: пока скетч живёт, сцена течёт без склеек. Морфинг делается своими функциями. Готового таймлайна нет.
- Типографика и голос: текст и звук есть, но кинетической типографики и привязки к озвучке нет.
- Запись: `saveFrames()` собирает кадры (PNG или JPG), `saveGif()` делает GIF. Для ролика этого мало, см. слабые стороны.
- Потолок качества (3 из 5): аккуратная учебная графика и генеративные эффекты; записи и постобработки уровня студий нет.

## Слабые стороны

- `saveFrames()` ограничен: длительность не больше 15 секунд, частота не больше 22 кадров в секунду (справочник p5.js). Для ролика нужен внешний захват: [ccapture-js](ccapture-js.md) или [remotion](remotion.md). Кадры, записанные в реальном времени, могут пропускать шаги.
- Движение «по номеру кадра» (`frameCount`) даёт повторяемость; движение «по времени» (`millis()`) нужно подменять при записи.
- Нет редактора сцены, нет таймлайна; крупные сцены быстро превращаются в длинный код.
- Две ветки: 2.x (основная) и 1.11.x (релиз-кандидаты в 2026 году). Часть API 2.x отличается (в заметках 2.3.4 упомянуто сообщение об ошибке при вызове `preload()`), старые скетчи из сети надо проверять.

## Сложность

- Для человека (2 из 5): простейшие команды, за день можно нарисовать первую анимацию. Красивая подача и ритм — недели.
- Для агента (2 из 5): код целиком. Агент пишет скетч и снимает кадры через headless-браузер. Руки нужны для оценки вкуса и настройки записи.

## Автоматизация и воспроизводимость

- Автоматизация (3 из 5): нет командной строки у самой библиотеки; запуск и запись делает headless-браузер или CCapture. Скетч — обычная веб-страница, поэтому подходит для Puppeteer. Сравнение способов — в обзоре [SVG, Canvas, WebGL](../classes/03-web-graphics.md).
- Воспроизводимость (4 из 5): проект — текстовый файл под git. `randomSeed(99)` делает случайность повторяемой («same results each time a sketch is run»). В README CCapture описан пример для p5: цикл ведут через `redraw()` при `noLoop()`.

## Платформа и оборудование

Любой современный браузер; есть веб-редактор. Для WEBGL нужна видеокарта или программный рендер.

## Экспорт

- Встроенно: PNG или JPG кадрами (`saveFrames`, до 15 секунд и 22 к/с), GIF (`saveGif`), одиночные изображения.
- Видео: через [ccapture-js](ccapture-js.md) (MP4 или WebM) или покадровый рендер.

## Когда брать и когда нет

- Брать: быстрые эскизы, генеративные фоны, простые симуляции и «живое рисование», когда автор знает JavaScript или нужен низкий порог входа.
- Не брать: формулы ([manim-ce](manim-ce.md)), аккуратная научная графика ([d3](d3.md), [mathbox](mathbox.md)), сложный 3D ([three-js](three-js.md)) и всё, что требует видеоредактора со звуком. Для настольной Java-версии смотри [processing](processing.md).
