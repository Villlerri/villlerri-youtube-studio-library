# Генерация кода анимации языковой моделью

Метод, а не продукт: языковая модель (чаще агент в цикле) пишет код анимации на [Manim](manim-ce.md), [Motion Canvas](motion-canvas.md) или [Remotion](remotion.md), запускает рендер, смотрит на результат и правит. Результат — обычный код под git, а не пиксели, поэтому его можно прочитать, исправить и воспроизвести. Для студии, которая работает с ИИ-агентами, это главный путь в классе.

## Что реально получается

Опора: статьи, README проектов, страницы проектов. Сами проекты я не запускал.

- TheoremExplainAgent (ACL 2025, устный доклад): агент строит планы, пишет код Manim и озвучку, делает длинные видео больше 5 минут. Бенчмарк TheoremExplainBench: 240 теорем, 5 автоматических метрик. Доля успешных рендеров зависит от модели: o3-mini 93,8%, GPT-4o 55,0%, Gemini 2.0 Flash 14,6%, Claude 3.5 Sonnet 2,1%; поиск по документации (RAG) помогает слабым моделям и вредит o3-mini (82,1%). Это модели начала 2025 года; сегодняшние сильнее, и числа нужно перемерить.
- По оценке TEA слабее всего «раскладка элементов»: 0,57–0,61 у моделей против 0,73 у видео, сделанных людьми; авторы пишут, что у большинства роликов «незначительные проблемы с раскладкой». Общий балл лучших агентов 0,77–0,79 при 0,77 у людей. Кроме того, видео вскрывают ошибки рассуждения, которых нет в тексте (пример с неверными стрелками).
- Code2Video (Show Lab, НУС): три агента — Planner (план и ассеты), Coder (код Python с «scope-guided auto-fix», автоисправлением по области ошибки) и Critic (модель зрения проверяет раскладку по «визуальным якорям»). Метрики: эстетика, эффективность кода и TeachQuiz (сколько знаний восстанавливает модель после просмотра). Авторы заявляют улучшение на 40% над прямой генерацией кода и ролики «сопоставимые с учебниками людей». Бенчмарк MMMC из профессиональных роликов.
- Generative Manim: веб-приложение и набор инструментов (GPT-4o, Claude, открытые модели), демо и платформа Animo. Идея: «любой создаёт анимации из текста». Количественных оценок в README я не видел.
- Math-To-Manim: по README многоэтапный конвейер: агент объясняет, проверяет математику, пишет сцену, ревьюит настоящие кадры рендера; заявлены фильмы по 3–4 минуты. Оценки со стороны нет.
- Типичные провалы (по перечисленным источникам): ошибки кода и рендера (поэтому нужен цикл автоисправления); наложения и выход за границы кадра (раскладка); смысловые ошибки в математике, видимые на рисунке; слабые модели почти не доводят до рабочего рендера. Для хорошего результата документированы: планирование перед кодом, поиск по документации Manim, критик по картинке.
- Непрерывность сцены, плавные превращения, камеру, рисование линий и синхронизацию с голосом даёт не модель, а библиотека, под которую пишется код. В Manim это превращения объектов, подвижная камера и озвучка через [manim-voiceover](manim-voiceover.md); детали в карточках библиотек. Метод даёт агенту доступ к этим возможностям. Ключевых кадров и «последнего кадра» как у видеомоделей здесь нет: положение каждого кадра задаёт код.
- Вывод: для объясняющих роликов метод надёжнее генеративного видео, потому что график, формула и схема задаются точно, а ошибка видна в коде и правится. Но верный результат с первого раза агент не гарантирует: нужен цикл «рендер, кадры, критик, правка» и проверка человеком.

## Слабые стороны

- Раскладка: самое слабое место во всех измерениях. Нужен критик по картинке и человек для финальной проверки.
- Математическая и физическая правильность не гарантирована: модель может нарисовать красиво и неверно. Проверять числа и формулы по источнику.
- Стиль: без своего оформления выходит однотипный «Manim по умолчанию». Нужен собственный дизайн-код. Это мой вывод, не измерение.
- Версии библиотек: Manim CE и ManimGL несовместимы, и модель может смешать их API. Это мой вывод, в источниках не измерено.
- Цена и время на ролик в статьях не приведены.

## Сложность

- Для человека (2 из 5): ставить задачу текстом и править код. Нужны основы Manim или другой библиотеки, чтобы понимать ошибки.
- Для агента (2 из 5): агент сам пишет код, рендерит и проверяет кадры (через ffmpeg и модель зрения). Руки нужны для финальной приёмки и озвучки.

## Автоматизация и воспроизводимость

- Автоматизация (5 из 5): всё из командной строки; пакетный рендер.
- Воспроизводимость (4 из 5): готовый код — текст под git, тот же код даёт тот же кадр. Сама генерация кода недетерминированна, поэтому в git кладут сгенерированный и принятый код, а не подсказку.

## Платформа и оборудование

Любая ОС, где работает выбранная библиотека. Нужны Python (для Manim), ffmpeg, часто LaTeX. GPU не нужна. Доступ к языковой модели: API или подписка.

## Экспорт

Определяется библиотекой. У Manim CE: mp4, mov, webm, gif, последовательность PNG; прозрачность только в mov и webm. См. карточки [Manim Community](manim-ce.md) и [Remotion](remotion.md).

## Когда брать и когда нет

- Брать: графики, формулы, схемы, векторные поля, диаграммы по данным; серии роликов с одним оформлением; всё, что нужно воспроизводить.
- Брать как основной метод агента: писать сцену кодом, рендерить в низком качестве, смотреть кадры, править.
- Не брать: фотореалистичные сцены, живые существа и «кино». Для них [Runway](runway.md), [Google Veo](google-veo.md) и другие, но с учётом физических рисков.
- Не брать без человека: финальную проверку смысла и вёрстки отдавать нельзя.
