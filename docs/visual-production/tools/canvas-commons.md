# Canvas Commons

Активный форк [motion-canvas](motion-canvas.md): TypeScript-библиотека с генераторами и веб-редактор с живым предпросмотром, метками времени и озвучкой. Форк сделан в августе 2025 года, когда у оригинала уже не было новых релизов. Сохраняет модель оригинала и добавляет набор текста, анимацию раскладки, кривые и более быстрый экспорт.

## Что изменилось по сравнению с Motion Canvas

Из блога, главной страницы и руководства по переходу:

- Пакеты называются `@canvas-commons/core`, `@canvas-commons/2d`, `@canvas-commons/vite-plugin`, `@canvas-commons/ffmpeg`, `@canvas-commons/editor` (раньше `@motion-canvas/ui`).
- Исправлена и расширена камера (автор отмечает проблемы в старой версии), обновлена библиотека цвета: цветовые пространства lab, lch, oklab, oklch, интерполяция цвета в `oklab`.
- Раскладка вместо DOM теперь на Yoga, анимированные изменения раскладки (`Layout.add`, `insert`, `remove` принимают длительность), явные оси позиционирования и преобразования origin.
- Текст: `Txt.split()` на графемы, слова, предложения; текст вдоль SVG-пути или кривой; перенос по алгоритму Кнута — Пласса, переносы слов, выравнивание по ширине; обтекание фигуры.
- Рисование: стиль Rough.js (штриховка, «нарисовано от руки»), лучше интерполяция путей, SVG и картинок.
- LaTeX: упрощённая правка формулы (`tex().edit(...)`, `replace` с `fade` и `morph`).
- Экспорт: новый WebCodecs-экспортёр на Mediabunny, примерно вдвое быстрее; экспортёр FFmpeg объявлен устаревшим.
- Копирование кадров и координат из окна просмотра.
- Требования: Node 20.19 и новее, Vite 4, 5, 7 или 8.

## Как перейти с Motion Canvas

Руководство называет переход «почти безвредным» (от Motion Canvas 3.17.0 или 3.18.0-alpha.0 к Canvas Commons 0.4.0):

1. Поставить пакеты `@canvas-commons/*` и удалить `@motion-canvas/*`.
2. В `vite.config.ts` подключить плагин `@canvas-commons/vite-plugin` вместо старого.
3. Заменить импорты `motion-canvas` на `canvas-commons`, `@motion-canvas/ui` на `@canvas-commons/editor`.
4. Подправить несовместимые места: импорты подпутей (`@canvas-commons/core/scenes` и подобные) больше не работают, всё берётся из корня пакета; свойство `offset` стало `anchor`; `relativeTo()` возвращает координаты в системе другого узла; Layout и Text перенесены на другие библиотеки, часть анимаций слегка изменится; `textWrap` по умолчанию включён.

Для агента: заменить имена и подправить несколько вызовов — работа для скрипта и проверки рендера.

## Что реально получается

- Непрерывная сцена. Анимация — генераторы без склеек, как в оригинале. Узлы остаются в сцене, меняются свойствами, выстраиваются раскладкой с анимацией, едут по путям. Формулы перетекают в узле Latex через `edit` и `replace` (`morph`, `fade`).
- Камера. Компонент `Camera`: `centerOn`, `rotation`, `zoom`, `reset`, всё можно запускать вместе через `all(...)`.
- Переходы между сценами. Готовые `slideTransition`, `zoomInTransition` и свои на генераторах. Если вызвать переход в начале сцены, предыдущая сцена остаётся в кадре на время перехода, рывка нет.
- Рисование линий: `Line`, `Path`, `Curve` с `start` и `end` дают рост контура. Стиль Rough.js для штриховки.
- Типографика: `Txt` с побуквенным и пословным делением, текст вдоль пути, перенос и выключка.
- Озвучка и временные события: `waitUntil('метка')`, метки двигают мышью в редакторе по звуковой дорожке. Это главное, чем форк и оригинал отличаются от Remotion и Manim.
- Презентационный режим: `beginSlide`, режим слайдов в браузере.
- Плеер для веба: `<canvas-commons-player src="sort.js">` встраивает анимацию в страницу, подходит для интерактивных статей.

## Слабые стороны

- Безголовый рендер не подтверждён. Рендер идёт из редактора по кнопке RENDER в браузере, командной строки для рендера нет. Блог 0.4.0 пишет про раскладку на Yoga, что это «ещё один шаг к безголовому рендеру», то есть самого безголового режима пока нет. Для проектов, которым нужна очередь рендера на сервере, остаётся [revideo](revideo.md) (тоже форк оригинала).
- Версия 0.x, API меняется между 0.2, 0.3, 0.4 (в документации три отдельных руководства по обновлению).
- Одного главного сопровождающего. В блоге автор форка сам пишет, что оригинал — «видение Джейкоба», а форк — его видение. Риск «автобуса» тот же, что у оригинала.
- Готовых математических объектов уровня Manim (оси, графики функций, векторные поля) нет, их рисуют сами.
- На GitHub нет релизов 0.3.0 и 0.4.0: теги в ленте только `0.2.0` от 2026-05-16, версия 0.4.0 есть в npm. Следить стоит за npm.

## Сложность

- Для человека (3 из 5): TypeScript, генераторы и сигналы нужно выучить. Редактор с предпросмотром и таймлайном упрощает отладку. Те же затраты, что у [motion-canvas](motion-canvas.md).
- Для агента (3 из 5): сцены пишутся кодом, но метки под озвучку двигают мышью, а рендер запускается в браузере. Агенту нужна оболочка (Playwright или аналог) и проверка кадров вручную.

## Автоматизация и воспроизводимость

- Автоматизация (2 из 5): нет командной строки для рендера, нет безголового режима, переменные проекта (`project-variables`) позволяют параметризовать ролик, но вызов остаётся через редактор.
- Воспроизводимость (4 из 5): проект — TypeScript под git, метки времени лежат в файлах проекта (в оригинале это `.meta` рядом со сценой, см. [motion-canvas](motion-canvas.md); для форка формат не проверял). Результат зависит от браузера, шрифтов и версии пакетов (смена Layout и Txt в 0.4.0 слегка изменила старые анимации).

## Платформа и оборудование

Node.js 20.19 или новее, Vite, браузер на движке Chromium для редактора. Linux, macOS, Windows. Видеокарта не нужна, нужен браузер с WebCodecs для нового экспортёра. Скачивать FFmpeg вручную не нужно, пакет ставит его сам (устаревший экспортёр).

## Экспорт

- Последовательность PNG (встроенный экспортёр) и видео. Новый экспортёр WebCodecs (Mediabunny) работает в браузере и кодирует видео и звук вместе. Старый экспортёр FFmpeg объявлен устаревшим.
- Альфа-канал: фон проекта можно оставить пустым, тогда он прозрачный (документация по рендеру).
- Разрешение, диапазон кадров, масштаб и частота кадров настраиваются в окне рендера. Цветовое пространство: sRGB или DCI-P3.

## Когда брать и когда нет

- Брать: объясняющее видео с голосом, где нужен редактор меток по озвучке, формулы и текст в одной сцене, плавные переходы и камера; новый проект, который иначе начали бы на Motion Canvas.
- Не брать: рендер на сервере без браузера (лучше [revideo](revideo.md), [remotion](remotion.md) или [hyperframes](hyperframes.md)); сложная математика с готовыми графиками ([manim-ce](manim-ce.md)); проект на версии оригинала 3.17 без возможности потратить время на переход.
